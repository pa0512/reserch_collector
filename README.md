# X(旧Twitter)アカウント収集システム

大学院の研究で、X上のBot的なアカウント群を調べるために作ったシステムです。
**指定した命名パターンのアカウントを探し、プロフィールとフォロー・フォロワー関係を、CSVに記録します。**

> ネットワークグラフの作成機能は、このバージョンでは含めていません(収集だけです)。

- サーバーでの動かし方: **[SERVER_SETUP.md](SERVER_SETUP.md)**
- Docker Desktop での動かし方: **[DOCKER.md](DOCKER.md)**

---

## 1. 全体の流れ

```
 ①ログイン状態を用意        ②収集                              ③結果
 (手動・最初に1回)

 ブラウザで手動ログイン   →   main.py                       →   accounts.csv
        │                      │                                (1アカウント1行)
        ▼                      ▼
   auth_state.json     アカウントを探す
   (ログイン済みの          ↓
    セッション)         プロフィールを取得
                            ↓
                       フォロー/フォロワー一覧を取得
                            ↓
                       CSVに記録(1アカウントごとに保存)
```

- 収集は、**人間がブラウザで操作するのと同じ範囲**(ページを開く・スクロールする・画面の文字を読む)だけを行います
- ログインは自動化していません。**人間が手動でログインした状態(Cookie)を、ファイルとして再利用**します

## 2. 設計の方針(やらないこと)

| やらないこと | 理由 |
|---|---|
| CAPTCHAの自動突破 | アクセス制限を回避しない方針のため |
| レート制限・アクセス制限の回避 | 同上。制限の兆候を検知したら、回避せずに停止する |
| プロキシの切り替え等による検知の回避 | 同上 |
| 非公開アカウントの情報の取得 | 非公開(鍵)アカウントは、検知してスキップする |
| パスワード等の、コードや設定への保存 | ログイン情報は、Cookieのファイル(`auth_state.json`)のみ |
| 複数プロセスでの並列実行 | 負荷を抑えるため。1つの調査セットにつき、1プロセスだけ |

## 3. ファイルの構成

| `profile_scraper.py` | プロフィールページから、作成月・リンク・フォロー数・フォロワー数を読み取る |
| `list_scraper.py` | フォロー一覧・フォロワー一覧を、スクロールしながら読み取る |
| `run_with_watchdog.py` | 収集を見張り、ログが一定時間止まったら(フリーズとみなして)自動で再起動する |
| `backfill_profile_links.py` | 記録済みのアカウントのプロフィールリンクを、後から取り直す(必要なときだけ) |

### ログイン状態の用意(お手元のPCで行う)

| ファイル | 役割 |
|---|---|
| `login.py` | ブラウザを開き、手動ログイン後に `auth_state.json` を保存する(画面が必要) |

> その場合は、普段使いのブラウザでログインし、Cookie-Editorなどの拡張機能でCookieをエクスポートして、`cookie_convert.py` で変換します。

## 4. 収集の仕組み

### 4-1. アカウントの探し方(優先順)

1. **`seeds`**: 最初に調べるアカウント(`--seed` または調査セットの `seeds`)
2. **既存データのフォロー・フォロワー欄**: 既に収集したアカウントの関係の中に、対象のパターンに一致する未調査のアカウントがあれば、それを次の候補にする(追加のアクセス不要)
3. **既知のアカウント名での検索**: 調査済みのアカウント名を検索して、関連して出てくるアカウントを探す
4. **検索の文字列**: 英字部分に 1〜9 を付けた9通り(例: `AmandaGarc1`〜`AmandaGarc9`)で検索する

候補は、名前の正規表現(`pattern`)に一致するものだけを採用します。

### 4-2. 1アカウントごとに取得するもの

- プロフィール: 作成月・外部リンク(プロフィール欄と自由記述欄内)・フォロー数・フォロワー数
- フォロー一覧・フォロワー一覧: アカウント名(`@`なし)

### 4-3. 止まっても大丈夫な仕組み

- **1アカウントごとにCSVへ保存**します。途中で止まっても、それまでの分は残ります
- **調査済みのアカウントはスキップ**します。再実行すると、続きから進みます
- **フリーズの自動検知**: `run_with_watchdog.py` 経由で実行すると、ログが3分更新されない場合に、プロセスを終了して再起動します
- **制限の兆候(エラー表示)を検知したら、その一覧の取得を打ち切り**、次に進みます

## 5. 出力データ: accounts.csv(1アカウント1行)

| 列 | 内容 |
|---|---|
| `screen_name` | アカウント名(`@`なし) |
| `account_created_at` | 作成月(例: `2024年1月`。Xが表示するのは月まで) |
| `profile_link` | プロフィール欄・自由記述欄にあるリンク(複数ならカンマ区切り) |
| `following_count` | プロフィールに表示されているフォロー数 |
| `followers_count` | プロフィールに表示されているフォロワー数 |
| `following_screen_names` | フォローしているアカウント名(カンマ区切り) |
| `followers_screen_names` | フォローされているアカウント名(カンマ区切り) |

- UTF-8 BOM付き(Excelでそのまま開ける)。1つのセルにカンマ区切りで入れるため、フォロー数が多いと、1セルが長くなります
- 実データの規模: **855アカウント、約150KB**(フォロー関係5,904件・フォロワー関係3,036件)

## 6. 使い方(日常)

```bash
# 収集(省略すると、既定の調査セット)
python main.py
python main.py --max-accounts 200                    # 1回で調べる新規アカウント数の上限(既定10)
python run_with_watchdog.py                          # フリーズ時に自動再起動

# 別の名前を調べる: 英字部分を指定するだけ(おすすめ)
python main.py --prefix StephanieL --max-accounts 3

# 調査セットの確認
python survey_config.py
```

サーバーでは、上の代わりに `./run_collect.sh ...` を、Docker では `docker compose run --rm app collect ...` を使います。

### 英字だけで指定する(`--prefix`)

`surveys.py` に書かなくても、英字部分を指定するだけで、別の名前を調べられます。

```bash
python main.py --prefix StephanieL --max-accounts 3
```

| 項目 | 内容 |
|---|---|
| 対象の名前 | `StephanieL` の後ろに数字が続くもの(`StephanieL55648` など)。**大文字・小文字は区別しません** |
| 検索の文字列 | `StephanieL1` 〜 `StephanieL9` |
| 記録先 | `accounts_stephaniel.csv`(英字は小文字になる) |

- 同じ英字で、もう一度実行すると、前回の続きから進みます
- `--seed アカウント名` で、最初に調べるアカウントも指定できます(複数回指定できます)
- 英字は、**3〜14文字**の、英字で始まる英数字です(短いと、無関係なアカウントが大量に該当するため)
- `surveys.py` に同じ英字の調査セットがあれば、新しいCSVを作らず、そちらを使います
- `--survey` とは、同時に指定できません

### 調査セットを追加する(複雑な設定が必要な場合)

`surveys.py` に、次のように書きます。

```python
"johnsmith": {
    "pattern": r"^JohnSmith\d+$",     # 対象の名前を表す正規表現(必須)
    "search_prefix": "JohnSmith",     # 検索の起点(省略可)
    "seeds": ["JohnSmith12345"],      # 最初に調べるアカウント(省略可)
    "examples": ["JohnSmith12345"],   # patternの書き間違い検出用(省略可)
},
```

記録先は `accounts_johnsmith.csv` と、自動で分かれます。
探索の起点(`search_prefix` / `search_queries` / `seeds` のどれか)が、最低1つ必要です。

## 7. 性能の目安

実際のログ(2026-08-18、約19分間・約30アカウント)から:

- **1アカウントあたり約38秒**(プロフィール取得+フォロー一覧+フォロワー一覧+待機)
- 100アカウント ≈ 1時間 / 1,000アカウント ≈ 10時間

待機時間(アカウント間に5〜12秒、スクロールごとに約2.5秒)は、負荷を抑えるために、意図的に入れています。
サーバーで長時間動かす場合も、この間隔は変えない前提です。

## 8. 既知の制限

| 制限 | 内容 |
|---|---|
| **一覧は約50件で止まる** | Xは、第三者に対して、フォロー・フォロワー一覧の先頭約50件しか表示しません(Chromeでの手動スクロールで確認済み)。プロフィールに「フォロワー135人」とあっても、取得できるのは約50件です。**記録された関係の数は、実際より小さくなります** |
| 一部の取得項目が空になる | 制限されたアカウントなどでは、作成日・フォロー数・フォロワー数が取得できない場合があります。空欄は「ゼロ」ではなく「不明」です |
| 検索の限界 | Xの検索は、同じ文字列を繰り返すと、結果が少なくなる(0件が続く)ことがあります。その場合、検索を打ち切ります |
| Xの画面の変更に弱い | 画面の内部の要素名(`data-testid`など)に依存して読み取っているため、Xの仕様変更で、取得できなくなる可能性があります |
| 取得できるのは、画面に表示される範囲のみ | APIは使っていません |

> **研究での扱い**: 「各アカウントの一覧は、先頭約50件までしか取得できない場合がある。したがって、
> 関係の構造は、取得できた範囲の見かけである」と、明記してください。

## 9. 利用上の注意

- **Xの利用規約**は、公式API以外での自動的なデータ収集を、原則として禁止しています。本システムは、技術的な回避をしない設計ですが、規約違反のリスクをなくすものではありません。使用にあたっては、研究室・所属機関の方針(倫理審査を含む)に従ってください
- **`auth_state.json` は、ログイン済みのセッションそのもの**です。パスワードと同等に扱い、他人に渡さない・共有フォルダに置かない・Gitにコミットしないでください(`.gitignore` に入れてあります)
- 収集データには、多数の第三者のアカウント名が含まれます。保存先のアクセス権限に注意してください
- 使用するXのアカウントは、凍結される可能性があります。研究用のアカウントを使うことを推奨します

## 10. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| ログインで「一時的に制限しました」と出る | Playwrightのブラウザでのログインが、自動化と判断された。普段使いのブラウザでログインし、Cookieを `cookie_convert.py` で変換する |
| `OSError: [Errno 22]`(Windows) | ダウンロードフォルダなど、書き込みが制限されたフォルダ。`C:\work` などに移す |
| `UnicodeEncodeError: 'cp932'`(Windows) | 文字コードの問題。`PYTHONUTF8=1` を付けて実行する |
| `No module named 'playwright'` | `pip install -r requirements.txt` と `python -m playwright install chromium` |
| `Permission denied`(`./setup_server.sh` など) | 実行権限が失われている。`chmod +x setup_server.sh run_collect.sh`、または `bash setup_server.sh` で実行する |
| 画面のないサーバーで、ブラウザが起動できない | `xvfb-run -a python ...` か、`X_SCRAPER_HEADLESS=1` で実行(`run_collect.sh` が自動で切り替える) |
| `別のプログラムが使用中です`(終了コード3) | 同じ調査セットの収集が、既に動いている。`ps aux | grep main.py` で確認する |
| `調査セットの設定エラー`(終了コード2) | `surveys.py` や `--prefix` の指定の誤り。表示された内容に従って直す |
